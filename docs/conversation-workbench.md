# 当天会话工作台

本地开发分支 `codex/today-chat-workbench` 从作者提交 `056187e9b55cb9181200e0911baab1e2480531d2` 开始。保留原信息看板，在同一服务增加「当天会话」入口。原部署脚本、提醒班次和录音服务仍可独立使用。

## 使用

用已安装下列依赖的 Python 启动，个人数据目录放在源码目录外：

```powershell
python -B scripts/chat_workbench.py --data-root '<个人数据目录>'
```

需要的依赖列在 `requirements-workbench.txt`。默认打开 `http://127.0.0.1:8711/conversations`，`--port` 可改端口，`--no-open` 不打开浏览器。`--refresh` 仅在启动时读取一次当天消息，不调用模型。页面显示读取时间；点击「更新今天」才能纳入随后落盘的新消息。

Windows 可用 `scripts/launch_chat_workbench.py --data-root '<个人数据目录>' --refresh` 隐藏启动服务并打开浏览器；重复启动会核对数据目录身份并复用同一服务，不叠加后台实例。

沿用本人已有的 `private/db_keys.json`（逐库密钥配置）和 `private/ai.json`（本机模型服务配置）。不运行原一键部署，不重复获取密钥、不注册计划任务。与原作者的单库主密钥格式不同，不能直接把 `db_key.json` 改名使用。所有新增状态保存在外部 `author-workbench/`，不会迁移旧版自动聊天开关。

- **当天总结**：每次重新读取所选群聊或私聊，从北京时间零点到读取时间的全部可读文字；消息多时分批归并，每项重点和待办均核对原文依据。旧历史、联系人记忆和口吻样本不参与总结。
- **多选总结**：勾选多个会话，或全选今天有消息的会话；每个会话单独生成结果并显示进度。某个会话失败会保留其他结果，停止后不再开始后续会话。
- **回复建议**：使用今天最近最多 80 条、合计最多 20,000 字符的消息生成可编辑草稿，显示实际使用条数。手工编辑不会被晚到的模型结果覆盖，切换会话也不混用草稿。
- **场景标签**：近期话题明确时显示日常、职场、客户或情感标签；信息不足时显示待确认。手动选择按账号和会话保存，优先于自动判断。
- **作者看板**：总结完成后，原看板的每日简报显示对应会话的概述与原文依据。私聊与群聊分别展示；这里只增加覆盖层，不改写原作者 `kanban/data.json`。

模型配置已有聊天处理授权时沿用；否则页面要求本人允许本次所选会话的当天文字交给显示的模型。切换账号、会话或服务后不沿用勾选。刷新、查看旧总结、切换标签都不发起模型请求。

主库落盘有延迟，尚未落盘、缺失分库、图片、语音、视频及文件正文不在可读范围内；页面展示覆盖条数和限制，不把未读取内容当成已经总结。当天为空时不调用模型。

## 本版边界

网页通过列表切换会话，按最新消息排序。Windows 页面上的「笺 · 悬浮窗」可打开或恢复会话笺；也可运行 `scripts/launch_conversation_note.py --data-root '<个人数据目录>'`。桌面依赖见 `requirements-note.txt`。

悬浮窗保留 Python 界面和数据处理，窗口识别与草稿填入使用独立 C# 组件；自动发送保持关闭，等待单独验收。组件只读已知标题控件路径，不扫描整个聊天控件树，不读取进程内存。普通生成建议仅在会话精确核对后填入，保留用户手写文字。

### 窗口联动修复版 0.1.3

修正固定比例坐标漏掉短标题、命中标题父控件后找不到子标题，以及大窗口误判标题位置的问题。未读取到标题和标题不在会话列表中分别提示；同名歧义仍不自动绑定。切出微信、标题暂时不可读或切换确认中时，保留已选会话、消息和草稿；只有明确识别到当前账号列表中的新会话才切换。保留显示不沿用窗口操作授权，填入前仍重新核对当前窗口。账号变化仍清空旧绑定。只通过离线虚构控件与回归检查，真实微信识别、流畅度和填入效果由使用者手动验证。

构建入口为 `conversation_engine/scripts/build_window_link.py --data-root '<个人数据目录>' --sdk '<dotnet.exe>'`。产物放在外部 `window-link/releases/`，核对后更新启动指针；保留正在运行的旧版本，不结束或重启窗口。用户须点小窗右上角「×」退出，再重新打开。

手动检查：让小窗处于「跟随」，分别打开一个私聊和一个群聊，停留约 3 秒检查标题；再改变微信窗口宽度并切换会话，检查小窗标题与当前会话一致。若失败，反馈小窗提示即可，不必提供聊天正文。识别通过后再分别检查建议填入与手写内容保护。

新增服务仅绑定本机回环地址，固定文件和业务接口白名单，写操作核对页面来源与临时令牌；不提供任意文件读取、命令执行或外部消息发送接口。

## 代码复用与验证

`conversation_engine/` 按白名单复用原会话笺的数据处理、模型客户端、场景规则、悬浮窗及独立窗口联动组件源码。`import-manifest.json` 记录导入文件摘要；导入脚本拒绝覆盖未核对的改动，后续可用 `scripts/import_conversation_engine.py --source '<原源码目录>' --check` 核对差异。`--update` 先核对已有副本与旧清单一致，再更新已审阅文件。来源和许可说明位于引擎自身 `PROVENANCE.md` 与 `skills/`，原作者仓库的 MIT 不扩大到此前混合项目的全部源码。本分支分享实验性源码，真实微信交互仍待手动验收。

```powershell
python -B scripts/verify_chat_workbench.py
```

验证使用合成账号、离线聊天和假模型，检查分批完整性、当天边界、账号与原文绑定、旧授权隔离、草稿操作及本机接口。真实微信的窗口交互不属于这些检查，也没有因此宣称修复。

`scripts/preview_chat_workbench.py --data-root '<新的外部演示目录>'` 可复现假模型界面演示。`scripts/smoke_workbench_model.py --data-root '<个人数据目录>' --output '<新的外部测试目录>'` 仅用虚构消息检查已配置模型的总结和回复格式，不读取真实聊天、不改变聊天授权。

## 分支发布检查

此分支包含源码、合成测试、通用界面素材和第三方许可，不携带个人配置、真实聊天、数据库、密钥、日志或本机编译产物。提交前运行 scripts/audit_publication.py --staged 检查实际暂存内容；提交后可用 --base <BASE_COMMIT> --revision HEAD 复查提交中的文件。可通过重复的 --private-json <外部配置文件> 只在本机比对已知敏感值，报告不会记录匹配内容。

自动检查不能证明任意聊天文字已匿名化，仍须审阅新增的示例、文档和素材。真实微信窗口识别、填入和性能由使用者手动验收，本次发布不新增真实微信操作授权。
