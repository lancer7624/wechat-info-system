# 微信 4.x 聊天记录导出 · 接手说明

> 本包不含任何密钥。目标机器需自己抓 key（两机密钥各自独立）。
> Frida 流程已在本机验证通过：微信 4.1.12.55 → 4.1.13.61（Windows 11），Frida 17.17.0。
> **微信 4.1.14 及以上**：Frida 链未适配，走「4.1.14 及以上机型」小节（wcdb-key-tool + import_dbkey.py）。

## 一、环境

```powershell
python -m pip install frida pycryptodome win11toast    # 完整依赖清单见 README《一、环境要求》
```

- Python 3 + Windows 10/11，无需管理员权限
- 微信需为 **4.x**（db_storage 布局）；3.x 不适用
- 依赖不止上面三个（还有 zstandard 等），**完整清单见 README《一、环境要求》**
- 多版本 Python 的机器：`where python` 确认装了依赖的解释器完整路径，下文命令里的 `python` 都换成它（否则可能被 PATH 里其他 python 抢位）

## 四、操作流程

### 第一步：抓 DB key（一次性，约 15 分钟）

> 微信 ≤ 4.1.13.x 走下面的 Frida 流程；4.1.14+ 直接跳到后面「4.1.14 及以上机型」小节。

```powershell
# 1. 完全退出微信（托盘右键退出，多开的所有账号都退）
python phase2e_login.py
#    脚本会 spawn 微信并弹 toast 提示 → 尽快登录/扫码
#    登录信号检测到后继续观察 120 秒 → 生成 candidates.json

# 2. 离线验证出 key
python phase3_verify3.py
#    命中 → 生成 db_key.json（敏感件，勿外传）
```

### 4.1.14 及以上机型：wcdb-key-tool（只读扫描，约 5 分钟）

Frida 链只适配到 4.1.13.x；4.1.14+ 改用社区工具扫每库现成密钥（纯只读，不注入、不改内存），再导入本包格式：

```powershell
# 1. 用包内 tools\wcdb_key_tool_windows.py（MIT，来源 github.com/TANGandXue/wcdb-key-tool，
#    需要最新版可去原仓库取）。微信保持登录运行，管理员终端执行（系统自带加密库，无需装依赖）：
python tools\wcdb_key_tool_windows.py extract   # 只读扫描 → all_keys.json（当前目录）
#    若提示扫不到：在微信里退出登录再重新登录，然后重跑一次

# 2. 转成本包的 db_key.json：
python import_dbkey.py all_keys.json
```

扫不到时的兜底：① [DbkeyHook](https://github.com/gzygood/DbkeyHook) 的 DbkeyHookCMD exe（不注入 DLL）；② 微信降级到 4.1.13 走上面 Frida 流程（key 跨版本/跨重登不变——抓到后升回新版依然有效）。

### 第二步：验证 + 导出

```powershell
python decrypt_db.py --count     # 6 库解密 + MAC 校验 + 表行数
python daily_export.py           # 增量导出（首跑自动补最近 24h）→ export\YYYY-MM-DD\*.md
```

### 第三步（可选）：图片 key

```powershell
# 微信运行中，先点开 2-3 张聊天图片触发渲染
python hook_image_key3.py        # attach 一次性只读 hook → image_key.json
```

### 日常自动化

- 每天 12:00 / 18:00 / 22:00 定时跑 `daily_export.py`（Windows 计划任务三班；同天多班重写全天目录，跨天首班按水位增量+回看 5 分钟防漏）
- 新消息检测（activity_check）按天维度对比，跨天自动重建基线，有新增才弹 toast

## 五、注意事项

1. **hook_image_key3.py 的 RVA 偏移只对 4.1.13.61 有效**。其他版本需重新静态分析定位（方法见文件头 docstring；脚本自带 .pdata 函数头校验，偏移错了会打印 ⚠ 非函数头）
2. phase2d_wide.py 的锚点是**从 DLL 自动提取**的，换微信版本改路径重跑即可，无需手工更新偏移
3. DB key 跨版本/跨重登不变（本机 4.1.12.55 抓的 key 在 4.1.13.61 依然有效）
4. WAL 环形复用不合并，主库快照可能滞后几条消息，次日 checkpoint 自动补齐
5. **纪律**：hook 全程只读、命中即 detach、不碰消息收发路径；db_key.json / image_key.json / export 目录均不外传
6. 本机日志路径示例：全部脚本按 `os.path.dirname(os.path.abspath(__file__))` 定位，包放哪都能跑
